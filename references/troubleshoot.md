# 排查：從 log 反推根因

> **一律先看 `dictate.log`，不要用猜的。** 它就在專案資料夾裡，每一筆都記下目標視窗、貼到哪、辨識到的前 40 字。

## 決策順序

1. 螢幕角落有小面板嗎？→ 沒有＝程式沒在跑（`Ctrl+Alt+V` 或雙擊 `啟動口述.bat`）
2. 錄音時音量條會跳嗎？→ 不會跳＝麥克風收不到（跑 `python doctor.py`）
3. 面板最大那行寫的目標對嗎？→ 不對＝右鍵取消，先點對的輸入框再重講
4. 面板說已貼上但字沒出現？→ 輸入框沒有游標。文字還在剪貼簿，按 `Ctrl+V`

## log 訊息對照表

| log 出現 | 意思 | 怎麼修 |
|---|---|---|
| `✗ 幾乎沒收到聲音（RMS …）` | 麥克風靜音／被別的程式獨佔／選錯裝置 | `doctor.py` 會檢查權限與裝置；會議軟體最常見獨佔 |
| `✗ 太短（不到 0.3 秒）` | 連點兩下了 | 這是開關不是按住：點一下開始、講、再點一下結束 |
| `✗ 有收到聲音但辨識不出` | 太小聲或雜訊太多 | 靠近麥克風；或模型太小（`tune.py`） |
| `⚠ 整理結果異常膨脹` | 整理模型把口述當指令執行 | 已自動改貼原文。內容偏指令性時把 `✨整理` 關掉 |
| `⚠ 搶不回目標視窗焦點` | 前景鎖擋掉了 | 已改放剪貼簿、沒有亂貼。按 `Ctrl+V` |
| `⚠ 焦點已不在原目標視窗` | 錄音中途切了視窗 | 已只貼上、沒自動送出（安全鎖，不是 bug） |
| `⚠ 熱鍵 … 註冊失敗（已被其他程式佔用）` | 別的常駐軟體先註冊走了 | 改 `config.json` 的 `hotkeys` 換一組 |
| `⚠ 剪貼簿寫入無法確認` | 剪貼簿被其他程式佔用 | 關掉剪貼簿管理工具再試 |
| `⚠ 修飾鍵一直沒放開` | 手指還按著 Ctrl/Alt | 放開再等一下；或改用滑鼠點面板 |
| `💥 … 未捕捉例外` | 真的有 bug | 把該段 log 開 issue |
| **完全沒有新行** | 熱鍵沒被收到／程式沒在跑 | 先確認程序存在；再確認熱鍵沒被佔用 |

## 常見要求怎麼處理

**「辨識不準」**
第一個動作永遠是**把常講的專有名詞加進 `vocab.txt`**（一行一個，常講的放上面，有 300 字上限）。這是準確度最大的槓桿，比換模型明顯。再不夠才跑 `python tune.py --bench` 換更大的模型。

**「輸出簡體字」**
裝 `opencc-python-reimplemented`，確認 `config.json` 的 `to_traditional` 是 `true`。

**「字跑到別的視窗」**
它貼回「**你講完的當下**」的前景視窗。錄音時面板最大那行就是目標，不對可**右鍵取消**。
若你有兩個視窗標題相同的 app（例如 Claude Code 與 Claude 桌面版，視窗標題都叫「Claude」、執行檔都叫 `claude.exe`），在 `dictate.py` 的 `APP_NAMES` 加一行「路徑片段 → 顯示名稱」就能分辨。

**「太慢」**
確認跑在 GPU（log 會寫 `模型就緒 GPU/...`）。退到 CPU 通常是缺 `nvidia-cublas-cu12` / `nvidia-cudnn-cu12`。沒有 NVIDIA 顯卡就跑 `python tune.py --apply` 換成適合這台的模型。

**「我不想讓任何東西出網」**
`config.json` 的 `polish.enabled` 設 `false`，或把面板上的 `✨整理` 點成灰色。聲音本來就不出網，整理層是唯一會送**文字**的地方。

**「有時候好、有時候壞」**
先問「什麼時候可以、什麼時候不行」。這個症狀底下常常疊著好幾個獨立問題——見 `references/pitfalls.md` 開頭那條母規律。
